# GitHub Tracking Plan

Use this repository as the durable record for code, curriculum decisions, implementation work, and instruction-quality findings.

## What Belongs In GitHub

- Product decisions and roadmap changes.
- Curriculum updates.
- Skill graph changes.
- Problem-template additions or corrections.
- Bugs, regressions, and failing tests.
- Assignment-generator rule changes.
- Data-model changes.
- Privacy and safety decisions.
- Anonymized learning observations that improve the method.

## What Does Not Belong In GitHub

- Full names of real learners.
- Grades tied to identifiable students.
- Private educational records.
- Raw homework submissions from real users.
- Sensitive demographic, medical, financial, or family details.

Use anonymized learner IDs when creating issues, for example `learner-a17`.

## Recommended Labels

- `bug`
- `frontend`
- `backend`
- `curriculum`
- `data-model`
- `assignment-generator`
- `pedagogy`
- `privacy`
- `logging`
- `documentation`
- `mvp`

## Issue Workflow

1. Open an issue for each meaningful bug, feature, curriculum change, or research question.
2. Link issues to commits and pull requests.
3. Record expected learning impact before implementation.
4. Record verification evidence after implementation.
5. Close only when the code, docs, and instructional rationale are updated.

## Milestone Structure

- MVP Foundations
- Diagnostic Engine
- Assignment Generator
- Persistence and Auth
- Instructor Analytics
- Learner Experience
- AI Assistance

## Release Notes

For each release, summarize:

- product changes
- curriculum changes
- known limitations
- verification performed
- any learner-data or privacy implications
